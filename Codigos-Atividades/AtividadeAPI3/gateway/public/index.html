💡 Questões para Discussão da Aula

Questão 1
Quando um backend único deixa de ser suficiente? Quais custos os microsserviços adicionam?

Um backend monolítico único deixa de ser suficiente quando diferentes partes do sistema passam a exigir escalabilidade assimétrica (ex: catálogo com tráfego 100x maior que a consulta detalhada), quando múltiplas equipes atuam no mesmo repositório gerando conflitos de deploy, ou quando domínios distintos precisam de tecnologias ou SLAs específicos.
Custos adicionados: Complexidade de rede (latência, falhas parciais e timeouts), necessidade de observabilidade distribuída (logs correlacionados por Request ID), gerenciamento de infraestrutura (múltiplas portas/processos) e orquestração de transações.

Questão 2
Onde implementar cache e como lidar com dados desatualizados ou falhas da PokéAPI?

Onde implementar: Em múltiplos níveis: no API Gateway (para rotas completas de catálogo), nos Microsserviços (em memória RAM ou Redis para entidades `/pokemon/:id`) e no Cliente/Browser (armazenamento de favoritos e paginação já visualizada).
Como lidar com falhas: Adotando o padrão Stale-While-Revalidate e Graceful Fallback. Como os dados da PokéAPI são praticamente imutáveis (as estatísticas de Pikachu não mudam a cada minuto), um cache com TTL longo (ex: 24h) garante que a aplicação permaneça 100% operacional mesmo durante indisponibilidade total da PokéAPI.

Questão 3
Por que usar apenas GET na PokéAPI e onde armazenar favoritos em uma solução com backend?

Por que apenas GET: A PokéAPI v2 é uma API pública estritamente de consulta (somente leitura), projetada para disseminar dados enciclopédicos sobre Pokémon para milhares de desenvolvedores simultâneos sem permitir alterações cadastrais.
Onde armazenar favoritos: As preferências são um dado específico do usuário. Na arquitetura distribuída, elas devem ser mantidas localmente no navegador (via localStorage) para consultas offline instantâneas, ou armazenadas em um microsserviço dedicado de usuários/favoritos com persistência em banco de dados relacional (ex: MySQL) ou arquivo JSON.
