Atividade Prática: aula-mysql
Tempo sugerido: ~10 minutos
01 / Introdução

Aplicação Fullstack com TypeScript & MySQL

Integração de interface web responsiva com backend Node.js e banco relacional persistente.

⚡ Backend

Node.js, Express e TypeScript com rotas REST e validação de schema.

🗄️ Banco de Dados

MySQL 8 com pool de conexões assíncronas e modelagem normalizada.

🎨 Frontend

Single Page Application em TypeScript puro sem dependências pesadas.

🎙️ Dica de fala (1 min): Apresente-se, mencione que o projeto aborda a construção de um CRUD completo de alunos com separação de responsabilidades e foco em segurança.
02 / Arquitetura

Arquitetura em 3 Camadas

Comunicação desacoplada e isolamento seguro de recursos.

🌐 Frontend (Navegador)

  • Não tem contato direto com o banco de dados.
  • Envia e consome exclusivamente JSON via Fetch API.
  • Renderiza estados de loading, sucesso e erro em tempo real.

🛡️ Backend & Conexão

  • Servidor Express valida cada requisição antes de tocar no banco.
  • Pool gerenciado pelo mysql2/promise na porta 3306.
  • Credenciais protegidas por variáveis de ambiente (.env).
🎙️ Dica de fala (1 min): Destaque o isolamento do banco. O browser nunca executa query direta; todo fluxo passa pelo backend que audita e valida os dados.
03 / Modelagem de Dados

Estrutura do Banco no MySQL

Definição DDL otimizada com integridade e padronização.

CREATE DATABASE IF NOT EXISTS aula_mysql
  CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;

CREATE TABLE IF NOT EXISTS alunos (
  id INT UNSIGNED NOT NULL AUTO_INCREMENT,
  nome VARCHAR(120) NOT NULL,
  email VARCHAR(160) NOT NULL,
  curso VARCHAR(120) NOT NULL,
  PRIMARY KEY (id),
  UNIQUE KEY uq_alunos_email (email)
);

✨ Suporte UTF-8 (utf8mb4)

Permite acentuação da língua portuguesa e caracteres internacionais.

🔒 Chave Única (UQ)

O MySQL rejeita automaticamente cadastros duplicados com o mesmo e-mail.

🎙️ Dica de fala (1 min): Explique as escolhas do DDL: o campo id unsigned auto-incremental e a regra de negócio do e-mail único delegada ao motor de integridade do MySQL.
04 / Backend & Pool

Gerenciamento Eficiente com Connection Pool

Escalabilidade e desempenho evitando custos de handshake TCP repetidos.

⚙️ Configuração do Pool

export const pool = createPool({
  host: process.env.DB_HOST,
  user: process.env.DB_USER,
  password: process.env.DB_PASSWORD,
  database: process.env.DB_NAME,
  connectionLimit: 10,
  waitForConnections: true
});

🚀 Vantagens Práticas

  • Reaproveitamento: Conexões permanecem vivas na fila.
  • Concorrência: Múltiplas requisições atendidas sem sobrecarregar o MySQL.
  • Health Check: Teste SELECT 1 durante o boot do servidor.
🎙️ Dica de fala (1.5 min): Explique por que abrir e fechar conexões a cada requisição é uma má prática e como o Connection Pool resolve esse gargalo.
05 / Segurança

Segurança & Prevenção de SQL Injection

Blindagem de queries com Prepared Statements e tratamento de exceções.

// ✅ Preparação segura contra injeção SQL
const [resultado] = await pool.execute<ResultSetHeader>(
  'INSERT INTO alunos (nome, email, curso) VALUES (?, ?, ?)',
  [novo.nome, novo.email, novo.curso]
);

🛡️ Parâmetros (?)

O driver trata qualquer caractere suspeito como dado puro, nunca como código SQL.

⚠️ Tratamento 409

Captura o código ER_DUP_ENTRY e responde com aviso amigável de e-mail duplicado.

🛑 Validação Prévia

Verificação estrita de e-mail regex e comprimento máximo de texto antes da query.

🎙️ Dica de fala (1.5 min): Ressalte que o sistema nunca usa concatenação de strings. Explique o fluxo de erro quando o banco retorna e-mail duplicado e como o backend traduz para HTTP 409.
